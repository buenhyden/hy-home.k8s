# Task: Validation Tooling Ownership Restructure

## Overview

Execute PLAN-0066 WP-001 through WP-012 as the delegated implementation of
Spec 0054 WP-010 and WP-011. Spec 0054 remains the integrated acceptance
owner. This Task is `done`; its parent-owned activation was established,
WORK-001 through WORK-012 are complete, and Spec 0054 recorded integrated
acceptance through TSK-0054-0011 before this closure.

The work moves and reuses the existing validation routing contract, corrects
current executable-reference and staged-index behavior, replaces production
self-tests with independent top-level tests, removes production fixture
dependencies, gives each rule one semantic owner, thins runners, simplifies
routing deliberately, and retires only wrappers and pins with sufficient
consumer and recovery evidence.

### WORK-012 Review and Verification

Independent review and broad execution of the uncommitted implementation
raised five findings, each remediated before commit. Two came from reading the
change, and three only appeared once the complete suite ran against the final
bytes; the earlier baseline predates the aggregate extraction and could not
have shown them.

The first is confirmed and would have failed the hosted `agent-governance-static`
job. WP-010 replaced the removed `--self-test` invocations with
`python3 -m unittest discover --start-directory tests --top-level-directory .`.
`tests/` is a namespace package, and `unittest` discovery has rejected
namespace start directories since Python 3.11, so that command raises
`ImportError: Start directory is not importable` on the pinned CI interpreter.
The workflow step, the delegated-command constant, the governance CI contract
record, the contract test constant, and the `tests/README.md` broad-discovery
example now use `--top-level-directory tests`, the form the existing regression
job already runs. The repository owns no second discovery convention.

The second is a consumer-zero surface introduced by the same work: the runner
exposed `--discover-gitleaks` for an aggregate that never called it, while the
runner's own child-environment projection remained the only real consumer of
that discovery. The flag was removed and `--lane` is required again, so the
runner keeps one entry contract and VAL-VTO-007 holds for surfaces this Task
added as well as those it retired.

The third is a stale contract in `tests/test_workspace_boundary.py`. It
asserted that the aggregate shell invokes `validate-workspace-boundary.py`
directly, which stopped being true when WP-008 reduced that shell to dispatch.
The intent moved to the current owners rather than being deleted: the registry
must route the production argv on the `all-files` lane with no self-test, and
the aggregate must delegate to the runner without embedding the rule.

The fourth and fifth share one cause and are the most consequential. WP-007
promoted shared bounded primitives, which gave `validate-affected-surfaces.py`
a `validation.repository.bounded_io` import, but the provider post-validate
fixture still copied the older file set. Both fixture payloads therefore failed
selection with `[hook] FAIL affected-surface path validation`. This is a
provider-hook execution path, not only a CI path, so the fixture file set is
treated as part of the hook's minimum contract and now names the promoted
module.

The ordered completion sequence then passed over the final implementation
bytes: affected and staged each selected 15 owners with no `FAIL`, `SKIP`, or
`DEFER`; plain staged pre-commit reported 17 passed with none failed; complete
discovery ran 861 tests with 4 expected skips and no failure; the registry
aggregate executed its declared owners and emitted one success marker; and
`pre-commit run --all-files` passed after its single mutation was isolated.
That mutation removed a trailing blank line in `scripts/archive_cutover_manifest.py`,
which predates this branch and is unrelated to validation ownership, so it was
committed separately to keep this scope clean. Diff checks are clean on both
the worktree and the index.

Two observations are recorded without change because they belong to other
owners: `validator_argv` still names the archive record template directly, which
predates this Task and belongs to the Archive contract; and the suites mutate
shared repository state, so two concurrent discovery runs produce spurious
failures that a single run does not.

The Task evidence text above was written after the complete suite ran. It is
documentation-only and is covered by the strict registry, Markdown, link, and
lifecycle gates plus the re-run affected, staged, and all-files lanes; no
implementation byte changed after the suite result.

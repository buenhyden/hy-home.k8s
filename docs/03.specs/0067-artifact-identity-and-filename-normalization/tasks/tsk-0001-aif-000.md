### WORK-001 Baseline

Read-only observation on 2026-09-01. These are audit findings, not invariants.

Stage 03 identity is fully derivable. All 54 Plans present `PLAN-<n>` where
`<n>` equals their package directory number, and all 343 Tasks present
`TSK-<n>-<seq>` with the same `<n>`. The target forms are therefore a
rearrangement of values the corpus already holds: `SPEC-<n>-SPEC-0001-PLAN-0001`, because
a package owns exactly one Plan, and `SPEC-<n>-TSK-<seq>` with the existing
sequence preserved. No number is invented and no package is renumbered.

Stage 90 member order is already declared. The pack router for
`0001-workspace-engineering` carries a 13-row member index whose order is
editorial rather than alphabetical. Member numbers follow that declared order,
so `m0001` through `m0013` preserve the pack's own reading sequence instead of
imposing a filesystem sort.

Stage 98 migrations carry a filename drift rather than an identity defect. All
nine records already present `MIG-####`, but six filenames begin with their
number while three retain a `mig-` prefix. Two naming conventions are live in
one directory, which WP-006 resolves.

Stage 98 tombstone identity is a derivation, not a stored label.
`scripts/archive_recovery.py` computes
`sha256(legacy_path + NUL + source_blob)` and both the identity and the
filename follow from it. The archived payloads carry no identity of their own,
so the target form must be derived from the recorded `original_type` and the
number in `original_path`.

The machine-loaded path inventory is closed and entirely outside scope: the two
gateway files import four Stage 00 policy, provider, and skill documents and
reference the roles and template directories; `.claude/settings.json` names four
Stage 00 hook scripts and the memory directory. None carries an artifact
identity, and none is renamed by this package.

### WORK-002 Verification

The pattern owners moved first. With the registry profiles and the frontmatter
union already naming the target forms, strict Markdown validation failed on 399
documents, which proves the contract was enforcing rather than permissive. The
corpus then converted and the same gate passed.

Conversion was arithmetic, not judgement. Every Plan already carried its
package number and every Task already carried its package number and sequence,
so the retired forms became `SPEC-<n>-PLAN-0001` and `SPEC-<n>-TSK-<seq>`
without inventing a value. One defect appeared during the sweep: the reference
pass rewrote the trailing group inside identities the frontmatter pass had
already produced, creating 55 double prefixes. These were repaired, and a
lookbehind sweep then reported zero retired forms outside sealed Stage 98
payloads.

Three second owners of the retired form were found only because the corpus
moved. `scripts/archive_validation.py` rebuilt a Task identity from the
filename as part of the archive recovery proof,
`scripts/validate-links-and-owners.py` rebuilt the same identity inside the
program lineage gate, and two test modules constructed it dynamically. Each now
names the current form. This is the duplication the Plan's global constraint
forbids, and it was invisible while only one form existed.

The sealed ledger keeps its historical value. The pinned Migration records the
identity each document carried when it moved, so the comparison projects that
value forward through a single helper instead of editing an archived record.

The retired Plan identity also carried a dead `CHG-` alternative that no
current document presented; it was removed with the pattern rather than carried
forward.

Strict registry, Markdown, cross-document, and lifecycle validation pass, and
complete discovery ran 861 tests with 4 expected skips and no failure.

## Approval and Safety Boundaries

- **Allowed Paths**: `docs/03.specs/**`, `docs/05.operations/**`,
  `docs/90.references/**`, `docs/98.archive/**` envelopes and derivation,
  `docs/99.templates/registry.json`, `docs/99.templates/contracts/**`,
  `docs/99.templates/templates/**` content, and the validators and tests that
  own these contracts.
- **Forbidden Paths**: Stage 00 governance document paths, Stage 99 template
  file paths, hook and provider configuration paths, sealed Stage 98 payload
  bytes, unrelated user changes, and live cluster or credential surfaces.
- **Additional Approval Required**: push, merge, pull request creation, any
  parent numbering change, and any change to a machine-loaded path.
- **Static Validation**: focused suites, affected and staged lanes, strict
  registry, Markdown, link, and lifecycle gates, archive recovery and
  validation suites, the repository aggregate, and diff checks.
- **Live Validation**: `DEFER` — this package changes repository documents and
  contracts only and proves no hosted, provider-runtime, or cluster behavior.
- **Secret / Vault Handling**: no secret or credential value is read or
  printed.
- **Rollback Plan**: per logical commit, one work package at a time; revert
  only the failed unit and never edit a sealed payload as rollback.
- **Evidence Location**: this Task for point-in-time execution evidence and
  reachable Git for rename and recovery history.

## Verification Summary

All nine work items are complete. The five strict gates -- document contract
registry, Markdown profiles, document lifecycle, links and owners, and agent
legacy cutover -- pass over the final bytes, and the full suite reports 858
tests OK with 4 expected skips.

Scope grew during execution. The domain identity keys (`migration_id`,
`incident_id`) were retired once measurement showed each repeated the value
`artifact_id` already carried, and `version` and `layer` were added to the
guided set. Both changes arrived as constraints after the Plan was written and
are recorded here rather than backfilled into it.

Nine byte-immutable Migration records were re-sealed under explicit
authorization. Each re-seal is a declared base -> proposed digest pair per path,
so every other sealed byte string stays rejected and the change is reviewed
rather than waived. Sealed ledger payloads were regenerated from their canonical
builders, never patched in place.

Both residual items recorded at first closure are now resolved. The WORK-108
artifact identity admission is removed with its projection helper, five pinned
constants, six imports it alone read, and its test class -- 123 lines that no
diff could reach, since its call site bound the result to an empty set. The
Stage 90 families each own a profile whose path and identity patterns are the
two halves of one binding, so an audit report can no longer claim a research
identity by matching a shared union.

One naming irregularity is deliberate. The research family's template keeps the
filename `reference.template.md` instead of gaining a family prefix, because
that path is the recorded destination of a move inside a sealed Migration
ledger and the recovery proof requires its targets to still exist. Renaming it
would either break that proof or rewrite what the archive says happened.

All evidence in this Task is repository-static and proves no provider runtime,
hosted CI, or live behavior.

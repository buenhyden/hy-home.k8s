# W03 YAML 1.2.2 Frontmatter Loader Technical Specification (Spec)

## Overview

This approved change contract closes handoff W03-H26 of the W03 stage of the external v14.7 execution package. The W03 task asks for frontmatter to be validated by the YAML and JSON Schema versions current consumers adopt, with YAML 1.2.2 and Draft 2020-12 as the target candidates; on 2026-11-13 the user chose to move to YAML 1.2.2 (W03-D29). SPEC-0181 recorded in `frontmatter_dialect` five frontmatter loaders on PyYAML 6, which implements YAML 1.1, with different duplicate-key and timestamp behavior. This package replaces them with one loader that reads frontmatter as YAML 1.2 as implemented by `ruamel.yaml`, with stated refusals, adds that library to the hashed CI lock, and updates the dialect record. W03-H26 named four loaders with unchanged timestamp rules; the read found five and this package unifies timestamps as text, which the Task records as an amendment of W03-H26. It starts after SPEC-0181 is implemented and merged, because it changes SPEC-0181's dialect record and tests. The [Task](tasks/tsk-0001-w03-yaml-frontmatter-loader.md) records execution and the [Plan](plan.md) orders the work.

## Strategic Boundaries & Non-goals

- In scope (writer W03, with W05 for validator code and W06 for the CI lock under the same-change rule): a new module `scripts/frontmatter_yaml.py` and its row in `scripts/README.md`; the frontmatter loading in `scripts/validate-markdown-profiles.py`, `scripts/document_lifecycle.py`, `scripts/validate-agent-governance.py` (frontmatter only), `scripts/validate-links-and-owners.py` and `scripts/validation/repository/quality.py` (Hookify local-rule frontmatter only); `.github/requirements/ci-validation.in` and the hashed lock regenerated by the command its header names; `docs/99.templates/registry.json` `frontmatter_dialect`, `scripts/document_contracts.py` and `docs/99.templates/contracts/document-profile.schema.json` only as the dialect record needs; `tests/test_frontmatter_key_contract.py` (`FrontmatterDialectTests`), the tests that pin loader errors, and a new loader test module with its exact route in `scripts/validation/registry.json` and its suite in `scripts/run-contract-tests.py`; the frontmatter paragraph of `.agents/governance/document-authoring.md`; an evidence row and the frontmatter `version` and `updated` of the SPEC-0161 Task (appended rows only); this package, the Stage 03 README and reviewed `.secrets.baseline` entries.
- Not in this package: YAML that is not document frontmatter, which keeps PyYAML (the `agents/openai.yaml` load in the agent-governance check, the workflow and kustomization loads in `quality.py`, and the other YAML loaders); `.github/workflows/`; any document text; installing into the user's local validation environment, which the user does with the command in the Git policy.
- No push, PR or merge without the user's approval, which is standing for this work (2026-11-13). Open question: none.

## Contracts

- **One loader.** `scripts/frontmatter_yaml.py` loads one frontmatter block with `ruamel.yaml==0.19.1` in safe, pure-Python mode at YAML version 1.2, in one pass, and returns plain Python values. It refuses, with one error type that carries a reason code and, for a duplicate, the key: a duplicate key, a `%` directive, an anchor or alias, a non-scalar key, any explicit tag including core tags such as `!!str` (no current frontmatter uses one, and quoting covers every need), a merge key, more than one document, and nesting that would raise `RecursionError`. It keeps every timestamp-like scalar a string. It accepts the YAML 1.2 core-schema scalars and ruamel's numeric extensions (`1_000`, `0b11`), which the Task records as accepted deviations. If the library is missing, it fails with a message that names the lock and the install command in the Git policy.
- **Call sites.** The five frontmatter loads call it and keep their current diagnostics: the profile check still reports `FM-DUPLICATE-KEY` with the key and its other YAML refusals as today; the lifecycle loader still treats a refusal as not a unique-key mapping; the agent-governance check still reports `AGENT-NATIVE-METADATA`; the links check still treats a refusal as no frontmatter, so a duplicate key, which it read last-wins before, is now refused; `quality.py` reports a parse failure with the loader's reason code rather than library text. Timestamps, which three loaders resolved to dates, are now text in all five; no code compares them as dates. The readers' existing input bounds (`MAX_REPOSITORY_INPUT_BYTES` and the bounded readers) are unchanged.
- **Lock.** `.github/requirements/ci-validation.in` gains `ruamel.yaml==0.19.1`; the regenerated lock adds exactly one hashed entry (a `py3-none-any` wheel with no required dependency) and changes no other pin; `scripts/validate-ci-python-contract.py` passes. Hosted CI installs the lock but runs no frontmatter loader in its style job, so the library is installed there unused; this is acknowledged.
- **Dialect record.** `frontmatter_dialect` keeps its shape: the five loader entries name the one loader, duplicate keys refused and timestamps kept as text; current is YAML 1.2 through `ruamel.yaml` 0.19.1 with the stated refusals and deviations; the target equals the current and is now asserted by the dialect test.
- **Policy text.** The document authoring policy's frontmatter paragraph names YAML 1.2 through the one loader.

[AD-0006](../../02.architecture/descriptions/0006-workspace-agent-governance-platform.md) owns the governance view; no component changes and no ADR changes.

## Data Modeling & Storage Strategy

No stored data changes beyond the dialect record. The CI lock gains one entry.

## Interfaces & Data Structures

- `scripts/frontmatter_yaml.py`: one load function and one error type with a reason code.
- Tests: each refusal above, timestamps kept as text, YAML 1.1-only booleans and sexagesimal forms as strings, octal forms, the accepted numeric extensions, a missing library, each call site's diagnostic, and a Hookify frontmatter case in `quality.py`.

## Edge Cases & Error Handling

- A value that YAML 1.1 and the new loader read differently would change a document's meaning; the implementation compares every tracked frontmatter block value for value once, records the result as Task evidence, and stops for the user's decision on any difference.
- Running a validator under a Python without the library fails with the loader's import message.

## Failure Modes & Fallback / Human Escalation

If the regenerated lock changes any other pinned package, the change is redone with only the new entry. If the local validation environment lacks the library, staged QA fails on the import, and the author asks the user to run the install command from the Git policy before the implementation commit.

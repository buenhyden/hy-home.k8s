# W03 YAML 1.2.2 Frontmatter Loader Implementation Plan

## Global Constraints

This approved work order follows the [approved Spec](spec.md) and inherits all of its boundaries. It adds two constraints: no document body or frontmatter value changes, and the diagnostics of the four strict document validators over the tree are equal before and after.

## Overview

Add one YAML 1.2 frontmatter loader on `ruamel.yaml` 0.19.1 with stated refusals, move the five frontmatter loads to it with their diagnostics kept, add the library to the hashed CI lock, update the dialect record and policy text, compare every tracked frontmatter block once, and have the user install the library into the local validation environment. [Task 0001](tasks/tsk-0001-w03-yaml-frontmatter-loader.md) owns execution and evidence.

## Context

A read of the tree and the pre-approval review's simulations on 2026-11-13 found five frontmatter loads on PyYAML 6: the profile check and the lifecycle loader on `SafeLoader` subclasses (the profile check keeps timestamps as text, the lifecycle loader resolves them), the agent-governance check (duplicate keys refused, timestamps resolved), the links check (plain `safe_load`, duplicates last-wins) and `quality.py` (Hookify local-rule frontmatter, duplicates refused). The same loader classes also read non-frontmatter YAML, which stays on PyYAML. No loader refuses anchors, aliases, non-scalar keys or directives today. The CI lock is generated by `pip-compile --generate-hashes`; adding `ruamel.yaml==0.19.1` (a `py3-none-any` wheel uploaded on 2026-01-02 with no required dependency) adds one entry and moves no pin, and the CI Python contract passes. The hook's environment check does not compare the environment with the lock, so a missing library shows as an import failure in the validators. All 248 tracked frontmatter blocks load to equal values under a prototype of the new loader. SPEC-0181's `frontmatter_dialect` and its dialect tests must be in the tree first.

## Goals & In-Scope

- Code: the loader module and five call sites with their diagnostics.
- Dependencies: the `.in` file and the regenerated lock.
- Registry and policy: the dialect record and one paragraph.
- Tests: the loader module, the call-site diagnostics, the dialect tests, the routing entry and suite.

## Non-Goals & Out-of-Scope

- Non-frontmatter YAML loads; workflows; document text; installing into the user's environment.

## Verification Plan

- Record the four strict document validators before any change.
- Build a scratch environment from the regenerated lock; show the loader tests failing first, then passing; compare every tracked frontmatter block value for value between the old and new loads once and record the result in the Task.
- Show the lock diff as exactly one added entry.
- Ask the user to install from the lock with the command in the Git policy before the implementation commit, and record the import check.
- Record in the Task the accepted ruamel deviations and the amendment of W03-H26 (five loaders; timestamps unified as text).
- Commit order: the package commit; then `.secrets.baseline` changes alone; then the implementation with the Task evidence. Run the staged lifecycle check before each commit and `graphify update .` after the code change.
- Record the risk class (`medium`: five validators, a new dependency in the CI lock and tests; no permission, trigger, hook or workflow file) and the core-diff checklist.

## Risks & Mitigations

Risks use the risk-report scale (likelihood Likely, Possible or Unlikely; impact Severe, Moderate or Minor), rated from the pre-approval review's evidence.

- **A new dependency in the commit-hook environment.** Possible, Severe: HIGH; it blocks the implementation commit until closed. Owner: W06 lock. It runs under the user's account in the hooks; it is closed by one exact version over ten months old, a hashed pure-Python wheel installed binary-only, no required dependency, and the CI Python and Actions security checks. Review cue: the lock diff. Signal that raises it: an unhashed, source-only or newly dependent package. Rollback: revert the implementation commit.
- **A validator fails to import outside the pinned environment.** Likely, Minor: MEDIUM, monitor. Owner: W03 author. The loader's import message names the lock and the install command. Review cue: an import failure. Signal that raises it: a manual run under system Python. Rollback: none needed.
- **A frontmatter value changes meaning.** Unlikely, Moderate: LOW, monitor. Owner: W05 code. All 248 blocks compare equal in the prototype, and the one-time comparison is recorded. Review cue: the comparison. Signal that raises it: a mismatch. Rollback: revert the implementation commit.
- **A ruamel behavior beyond YAML 1.2 is accepted unnoticed.** Possible, Minor: LOW, monitor. Owner: W05 code. Tags, merge keys and directives are refused and the numeric extensions are recorded. Review cue: the loader tests. Signal that raises it: an unexpected value type. Rollback: add a refusal.
- **Lock regeneration moves other pins.** Unlikely, Moderate: LOW, monitor. Owner: W06 lock. The review's regeneration added one entry only; the diff is checked. Review cue: the lock diff. Signal that raises it: a changed pin. Rollback: regenerate with the other pins held.
- **The hosted style job installs an unused package.** Possible, Minor: LOW, monitor. Owner: W06 lock. Acknowledged in the Spec. Review cue: the hosted install log. Signal that raises it: a hosted failure from the package. Rollback: revert the lock entry.

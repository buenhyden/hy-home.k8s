### WP-002 result: the retirement is blocked, and why

The retirement stopped at the condition the Plan declared. Three attempts were
made and each was refused by a different clause of the same sealed record.

Deleting the ledger raised `RECOVERY-MIGRATION-TARGET`: `MIG-0005` is sealed and
its historical-consumers block names the ledger as a path that must be a tracked
regular blob. Truncating it in place, which would have kept the path and dropped
the body, then raised `RECOVERY-MIGRATION-CONSUMER`: the same proof requires a
consumer's current bytes to equal its bytes at the recorded source commit. The
ledger is therefore byte-frozen, not merely required to exist. A sealed
migration is terminal, so `MIG-0005` cannot be edited to lift either clause.

This measures why Spec 0054's approved progress-owner retirement never
completed: under the current rule it could not. The 938488-byte body and its 232
commit pins stay until that rule is revisited, which is a change to a recovery
proof and not a decision this execution may make alone.

The contradiction itself is corrected at the owners that can be changed.
`memory/README.md` now states that the ledger header is historical text under a
byte freeze rather than an instruction, and names this README as the authority
for what may be written there; `policies/context-and-memory.md` records the same
freeze and its consequence for the retirement.

A sequencing error is recorded rather than hidden. MIG-0007 was opened as a
draft before the redirect was proved, against this Plan's own instruction to
prove first. A draft migration cannot be deleted either, so the premature record
was removed from unpublished history rather than left as a migration that could
never seal. The rule-conflict fix it uncovered was kept.

### Rule conflict found and fixed

Opening any migration was impossible in a green commit. `document_lifecycle`
admits a migration only in `draft`, refusing `absent -> sealed`, while
`parse_migration_control` refused anything not sealed and took the whole
repository's recovery proof down with it. Spec 0063 recorded this as a
two-change procedure without naming the cause. A draft is not evidence, so it is
now skipped rather than refused, and `LIFECYCLE-DELETE` still reads only sealed
rows. The sealed-only assumption was duplicated across five discovery paths with
no single owner; `is_sealed_migration` is now that owner.

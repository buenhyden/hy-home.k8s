# W03 H2-List Model Removal Technical Specification (Spec)

## Overview

### Intent

This approved change contract is the seventh and last phase-3 package of the W03 stage of the external v14.7 execution package, in the order W03-D49 fixes. Once SPEC-0203 has moved the Task role, every document role that has documents carries a form, and this package removes the H2-list model that the forms replaced: the `sections` lists of the registry profiles, the heading lists that were derived from a form for the old readers, and the list checks that no current document can reach (W03-H02). It is the change that ADR-0059 Decision 5 names, as ADR-0062 narrows it under W03-D52: the profile lists and their checks leave, and the retained H2 lists of the accepted ADRs ADR-0001 to ADR-0061 stay as a registered extension with their checks. The numbers follow W03-D69: ADR-0061 is the amending ADR of SPEC-0207, the ADR of SPEC-0198 is ADR-0062, and the retained range ends at ADR-0061. On 2026-11-14 the user decided the three choices this package raised with the answer `w03 프롬프트에 작성된대로`, as written in the W03 prompt (W03-D63), which the task file `tasks/TASK-hy-home-k8s-W03.md` of the v14.7 package resolves as follows. The `sections` key leaves every current profile and the current schema, and the strict registry check refuses it, because line 757 leaves no differing H2 or required field as a permanent compatibility layer, line 878 makes the removal of the old operating system no permanent deprecation layer, and rule 3 of `scripts/AGENTS.md` keeps no compatibility branch for an older format. A profile whose mode is `authored`, `router` or `template` must have a form, except the `provider-native` role, because line 759 allows a no-change conclusion only when each registry entry is shown to meet the target contract and lines 113 and 875 do not force a surface that does not apply to a role. The third answer of W03-D63, an integer raise of `schema_version` from 10 to 11, no longer holds. A requirement audit compared the package with the W03 prompt, and the user resolved its findings on the same day with `W03 프롬프트에 작성된대로` (W03-D65): the value is not chosen here, because line 862 treats the registry serialization version as the data-structure contract of the code that reads the registry and moves an existing integer only by an explicit mapping after a reader analysis, and line 890 forbids converting it wholesale. SPEC-0207 does that analysis under W03-D66, which supersedes the third answer: `schema_version` becomes a SemVer string, generation 10 maps to `10.0.0`, SPEC-0207's own change of type lands the registry at `11.0.0` right after SPEC-0191 and before every other package, and each later registry change applies the bump rule of lines 877 to 882. Under that rule this package is a MAJOR step, because it removes a required key and refuses input that was valid before (line 877): it raises the MAJOR number of the version the registry carries when it lands and sets MINOR and PATCH to 0 (line 882). This package's commit records the W03-D63 row in the [SPEC-0161 Task](../0161-w00-v14-7-delta-intake/tasks/tsk-0001-w00-v14-7-delta-intake.md) with the user's answer, these resolutions and their prompt lines; W03-D65 is recorded there by the SPEC-0193 package commit and W03-D66 by that of SPEC-0207. A read of `main` at `81096a83` found 85 profiles and 21 forms; every profile carries a `sections` key, 12 of them non-empty, all on the six SDLC roles that SPEC-0195, SPEC-0197, SPEC-0198, SPEC-0200 and SPEC-0203 move; 15 profiles have no form and no list. The counts are taken again at the rebase; they hold at `a8c689e5`. The [Task](tasks/tsk-0001-w03-h2-list-removal.md) records execution and the [Plan](plan.md) orders the work.

## Behavior Contract

### Normal Behavior

Contracts:

- **Preconditions.** Every package from SPEC-0191 to SPEC-0204 has merged, SPEC-0207 among them in its place after SPEC-0191. Of those this package depends on the form packages, SPEC-0195, SPEC-0197, SPEC-0198, SPEC-0200 and SPEC-0203 after SPEC-0186 to SPEC-0189, so the 12 SDLC profiles carry empty lists like the other 73, on SPEC-0196 and on SPEC-0207; SPEC-0204 and the other Policy rule-ID packages precede it by order only. SPEC-0207 has merged, right after SPEC-0191 (W03-D66): `schema_version` is a SemVer string, `registry_schema_version` in `scripts/document_contracts.py` is the one function that reads it, `REGISTRY_MAJOR` in `scripts/document_authority.py` holds the MAJOR the readers implement and `READABLE_REGISTRY_MAJORS` the MAJOR numbers the history reader reads, the write guard holds its standard-library copy `DOC_REGISTRY_MAJOR`, the loader and the guard refuse any other MAJOR, `registry_at` reads every generation in `READABLE_REGISTRY_MAJORS` with that commit's own typed reading, the tests that pin the version read the constants, and ADR-0061, the amending ADR of SPEC-0207, has replaced the sentence of ADR-0059 Decision 1 that fixed the value at 10. The Task records, after the rebase, the count of lists and the version then on `main`.
- **Registry key (W03-D63).** The `sections` key leaves every current profile. The current schema drops the property from the profile definition, so the schema refuses a profile that carries it, and the strict registry check refuses it as well with its own diagnostic. The authority guard drops the key from the profile key set. The current schema and the current readers admit no list in any form other than the `retained_sections` of a retained form. No current input keeps the old shape.
- **Registry Schema Version (W03-D65, W03-D66).** The level is MAJOR under the bump rule of SPEC-0207. Line 877 rates a removed required key and the refusal of earlier valid input as MAJOR even when every consumer is fixed in the same change, and the new rule for profiles without a form is a stricter obligation of the same level. One release unit takes its highest level once (line 882), so the commit that removes the key raises the MAJOR number of the version then on `main` by one and sets MINOR and PATCH to 0: the next MAJOR over the value on `main`, whatever the packages in between have set. In this Spec the MAJOR number before that commit is the retired MAJOR and the one after it the new MAJOR. This package chooses no other value, and its Task records the level, the reason and the value before and after as evidence. The registry and the `const` of the schema carry the new value, `REGISTRY_MAJOR` is set to the new number, which is appended to `READABLE_REGISTRY_MAJORS`, and the guard's copy `DOC_REGISTRY_MAJOR` is set with it, all in that one commit; this package adds no other place that holds the number and edits no test for the bump, because the version tests of SPEC-0207 read the constants. A registry of the new MAJOR that carries `sections` is refused, and a registry of the retired MAJOR at the current path is refused by the reader rule of SPEC-0207.
- **History reader (W03-D66, line 778).** `registry_at(commit)` obtains the version of a commit's registry through `registry_schema_version` and never compares the raw value. SPEC-0207 makes it read every generation whose MAJOR is in `READABLE_REGISTRY_MAJORS`, the integer generation 10 included, with that commit's own typed reading, and this package keeps the replay of every generation in that tuple: it appends the new MAJOR and removes none. A registry of the new MAJOR is read with the current typed reading, which builds no heading list. A registry of an earlier MAJOR in the tuple, which carries `sections`, is read with a history reading that builds the heading lists that registry carried, so the replay of an earlier commit gives the result it gave before this package. A generation outside the tuple keeps the treatment SPEC-0207 gives it, and the integer branch of the mapping function stays as SPEC-0207 defines it, for replay only. The history reading is a history-replay reader and not a compatibility layer for current input: it never reads the current registry or a current document, the current path refuses every earlier MAJOR, and its only callers are the replay of an earlier commit by the cumulative-history check and the base side of the staged check. Line 778 of the W03 prompt keeps the cumulative-history replay until the transition, so this replay-only branch with its removal condition is required; it is not the compatibility branch that rule 3 of `scripts/AGENTS.md` forbids, which would read a current input in an old shape. It stands beside the old-shape branches of SPEC-0200 and SPEC-0203 and the integer branch of SPEC-0207, which serve the same replays. It is removed, with its tests, when `READABLE_REGISTRY_MAJORS` no longer holds a MAJOR below the new one, which SPEC-0207 allows only when the replay window no longer reaches a commit of that MAJOR; the package that removes it records that fact.
- **Write guard.** `scripts/provider_write_guard.py` runs from the checkout with the standard library only, so it holds its own copy of the implemented MAJOR, `DOC_REGISTRY_MAJOR`, and fails closed with `HOOK-DOC-REGISTRY` for a registry of any other MAJOR; a consistency test of SPEC-0207 compares the copy with `REGISTRY_MAJOR`. It judges every structured write against the registry in the working tree, so a tree in which the guard and the registry disagree on the MAJOR accepts no structured write. `DOC_REGISTRY_MAJOR` moves in the same commit, in the order the Plan fixes, the committed guard never accepts two MAJOR numbers, and the consistency test keeps passing unedited. No permission, trigger or hook registration changes.
- **Typed reader.** The current typed reading builds no heading list from a profile. `_form_headings`, which builds required and allowed H2 lists from a form so that list readers keep working, is deleted. The field that holds the lists of a registry of an earlier MAJOR is renamed, so a reader that still asks for the old field fails loudly instead of reading an empty list.
- **Readers of the heading contract.** Each current reader takes the H2 it needs from the form, or from the retained lists where a retained form applies, through one accessor: the lifecycle evidence reader of the link validator (required and allowed H2), the form contract check of templates (required H2), the quality gate's test for a heading contract (a profile with a form has one), and the template parity check of the registry validator (parity of the form). For a registry of an earlier MAJOR the same accessor returns that registry's lists where a role had no form yet. A fifth consumer is a history reader: the old-shape Plan branch of SPEC-0200 in `_local_plan_task_contract_issues`, which asks through one accessor function of its own whether an earlier registry's Plan profile allows `Promotion`. This package re-points that function to the accessor, a one-line change, and changes nothing else in the branch, so `PLAN-PROMOTION`, `PLAN-GLOBAL-CONSTRAINTS` and `TASK-PARENT-APPROVAL` still fire on the replay of an old commit. The old-shape Task reads of SPEC-0203 take their section from the evidence binding and not from a list, apart from the heading read of the link validator, which is the first of the four; if the rebase shows another old-shape read of a list, it moves onto the accessor in the same way and the Task records it. No reader keeps a second source.
- **List branch of the body check.** The profile validator checks a document against its form tree. The list branch stays for one case only, a retained form, and with it `BODY-HEADING-REQUIRED`, `BODY-H2-ORDER`, `BODY-H2-DUPLICATE`, `BODY-HEADING-UNSUPPORTED`, `BODY-HEADING-EMPTY` and `BODY-HEADING-NESTED-ROLE`, which ADR-0062 keeps for the accepted ADRs in the closed range, ADR-0001 to ADR-0061. The three identifiers that only a README profile in list mode could produce, `README_H2_REQUIRED`, `README_H2_DUPLICATE` and `README_H2_UNSUPPORTED`, are removed: every README role has had a form since SPEC-0178, no retained form can reach them, and no test or text names them.
- **Registry rules.** `REGISTRY_FORM_LEGACY_LISTS` becomes the rule that refuses the `sections` key on any profile of the current registry. `REGISTRY_BODY_SECTION` requires a body contract's section to be a required H2 of the role's form and no longer falls back to a list. The README navigation check drops its list half.
- **Profiles without a form (W03-D63).** `REGISTRY_FORM_REQUIRED` refuses a profile whose mode is `authored`, `router` or `template` and whose role has no form, except the `provider-native` role (W03-D33); a `native` or `non-target` profile may have none. No list of profile identifiers is kept. At `81096a83` 15 profiles have no form and no list, so the profile validator applies no heading rule to them before or after this package; it still applies the fence, frontmatter mode and placeholder checks, and the registry validator still requires one route for each tracked path. They are the six `provider-native` profiles (`.claude/agents/`, `.claude/commands/`, `.codex/agents/` and their three templates), which the agent-governance validator, template parity and the TemplateDefinition record of SPEC-0196 check, and nine without a role, each `native` or `non-target`: the root `CLAUDE.md`, the folder `CLAUDE.md` imports, the skill reference and asset files, the two provider baselines, the GitHub control files, `CHANGELOG.md`, `RTK.md` and the raw evaluation outputs. The Task records, for each of the 85 profiles, that it meets the rule and by which clause.
- **Retirement order.** The list checks are retired in the order the work lifecycle sets. First their protection is shown transferred: the Task maps each rule of the list branch to the tree rule, or the retained form, that covers the same documents, and a mutation of one document per role in a temporary copy still fails. Then their callers and registration go: the derived lists, the registry key, the old meaning of the registry rule and the three README identifiers. Last go the helpers, fixtures and tests that only they used, each after a search shows no other consumer. A test that still protects something reachable is rewritten onto a retained form or a registry of an earlier MAJOR and is not deleted.
- **Policy text.** The document authoring policy and the Stage 99 README say that a profile's headings come from its role's form, that no profile carries H2 lists, which profiles may have no form and which checks cover them, and that the accepted ADRs keep their retained lists under ADR-0062. A current policy text that names the value of the version takes the new one; no ADR changes.

### Failure and Edge Cases

Edge cases and error handling:

- The merge order is SPEC-0191, SPEC-0207, SPEC-0192 to SPEC-0204, then this package; SPEC-0206 follows it. It depends on every form package (SPEC-0186 to SPEC-0189, SPEC-0195, SPEC-0197, SPEC-0198, SPEC-0200 and SPEC-0203), on SPEC-0196, which retires the heading-line table path first, and on SPEC-0207 for the form of the version, its reader function and its bump rule. The Policy rule-ID packages, SPEC-0204 among them, share only the registry and the SPEC-0161 Task with it.
- If a package in between raises the MAJOR number, the retired MAJOR is that later number and this package still raises it by one. A MINOR or PATCH step of another package changes only the value this package starts from.
- A branch that was cut before this package holds a registry and a guard of the retired MAJOR; it keeps working until it rebases, and after the rebase it holds both at the new one.
- The commit that changes the version has a base of the retired MAJOR and a proposed registry of the new one; the staged check of SPEC-0203 reads the base with the history reading.
- SPEC-0207 makes `registry_at` read every generation in `READABLE_REGISTRY_MAJORS`, the integer generation 10 included, with that commit's own typed reading. This package keeps every number in that tuple and changes only what reads an earlier registry: the history reading, which still builds the lists that registry carried. The replays of a commit of the retired MAJOR and of a commit that holds the integer show it.
- A heading reader that was missed would see an empty list and pass every document. The renamed field turns that into a failure, and the mutation run shows each role still refused.
- If SPEC-0207 merges with another reader rule, another function name or another reader of the version than this Spec names, this package follows what merged and moves every reader that pins the MAJOR in the same commit; the Task records the difference.
- The counts and the places named are those of `81096a83`; five form packages, SPEC-0196 and SPEC-0207 change them before this package starts.

Failure modes and fallback or human escalation:

If a profile still carries a non-empty list, if SPEC-0207 has not merged or an accepted ADR still fixes the value of `schema_version`, if a current document of any role passes after a required H2 is removed from it, if the replay of an earlier commit changes its result, if the write guard cannot be changed without a tree state that blocks every write, or if a test can be kept only by weakening what it asserts, the author stops and asks the user. If any document gains or loses a diagnostic, the change is wrong and is fixed before commit.

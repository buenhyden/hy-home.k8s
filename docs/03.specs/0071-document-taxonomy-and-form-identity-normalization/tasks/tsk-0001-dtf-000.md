## Approval and Safety Boundaries

- **Allowed Paths**: `docs/**` authored documents and routers,
  `docs/99.templates/registry.json`, `docs/99.templates/contracts/**`,
  `docs/99.templates/templates/**`, Stage 98 envelope frontmatter and its
  generation contracts, `README.md`, and the validators and tests that own
  these contracts.
- **Forbidden Paths**: sealed Stage 98 payload bytes, authored document paths
  outside Stage 99, hook and provider configuration paths, unrelated user
  changes, and live cluster or credential surfaces.
- **Additional Approval Required**: commit, push, merge, pull request creation,
  and any change to a machine-loaded path.
- **Static Validation**: strict registry, Markdown profile, link/owner, and
  lifecycle gates plus the full unit suite and the repository quality gate.
- **Runtime Evidence**: none claimed. Every check reads tracked repository
  bytes only; no live cluster, provider runtime, or hosted CI result is
  asserted.

### Measurement limitations

- The suite was executed per module in parallel to bound wall-clock time. Under
  that load `test_run_validation_lane` reported one failure in its process-reaping
  case; the module passes when run on its own, so the failure is a property of the
  parallel harness rather than of the repository.
- The Stage 98 archive modules read staged blobs. They are only meaningful when
  the index and the worktree agree, so they were run with no concurrent staging.
- `validate-agent-legacy-cutover` fails closed between a byte change and its
  historical-consumer re-pin, because the coverage has to name a commit that
  already carries the new bytes. Commits one and two therefore each report the
  consumers the following commit re-pins; the branch tip reports zero.

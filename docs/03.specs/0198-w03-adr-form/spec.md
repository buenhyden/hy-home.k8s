# W03 ADR Form Technical Specification (Spec)

## Overview

This approved change contract is the fourth phase-3 package of the W03 stage of the external v14.7 execution package, in the order W03-D49 fixes. It gives the ADR role its COMMON-DOC-FORM-1 1.0.0 form in the Stage 99 registry, gives the decision template its TemplateDefinition with the full record that SPEC-0196 checks (W03-H13) and moves the template to the form (W03-H02). It is a template-only migration: W03-D02 keeps every accepted ADR in the form it was accepted in, so no ADR in the tree changes form. 35 of the 36 at landing are byte-identical; ADR-0059 gains one dated clarification paragraph, as the ADRs that ADR-0060 narrowed did under SPEC-0185 (W03-D40). It applies W03-D52 in two parts, with its bound amended once and openly by W03-D69 before anything lands: on 2026-11-14 the user decided "`Retain through 0061`", so the retained list is every ADR accepted before this package lands, ADR-0001 to ADR-0061, and not ADR-0001 to ADR-0060. The added identity is ADR-0061, the amending ADR of SPEC-0207 (the Registry Schema Version package, which lands right after SPEC-0191), written in the form of its day; this package's own ADR therefore moves from ADR-0061 to ADR-0062, which takes the common form. SPEC-0207's commit appends the W03-D69 row to the SPEC-0161 Task. First, the accepted-ADR exception is a retained form bounded by a closed identity range, ADR-0001 to ADR-0061, so an ADR written after this package takes the common form in every status, accepted included. Second, because that retained form keeps H2 lists and their checks alive, a new amending ADR narrows Decision 5 of ADR-0059, which says the change that moves the last role removes the lists and their checks. It also applies W03-D03 (`Lifecycle Traceability` stays a registered local H3 under Traceability) and W03-D08 with W03-D57 (the common contract's role table is registered with no minimum row and nothing is renamed), recorded in the [SPEC-0161 Task](../0161-w00-v14-7-delta-intake/tasks/tsk-0001-w00-v14-7-delta-intake.md). A read of `main` at `8daf643f` found 35 ADRs (36 once ADR-0061 of SPEC-0207 is accepted, which is the count at landing), 284 KB together, all `accepted`, with identities from ADR-0002 to ADR-0060, all inside the range; every one carries the same seven H2 in the same order, 34 carry `layer` and ADR-0060 does not. The `retained_form` extension kind exists since SPEC-0168 (`git show 9265b507:docs/03.specs/0168-w03-common-form-model/spec.md`) and no form uses it yet; it selects by status alone, and the profile validator then replaces the form tree by the retained lists, so an ADR accepted in the common form would fail today. The `layer` rule takes the same identity bound; that applies W03-D22 and W03-D52 and needs no new decision row, and the Task records the application at implementation. The [Task](tasks/tsk-0001-w03-adr-form.md) records execution and the [Plan](plan.md) orders the work.

## Contracts

- **ADR form.** `common_forms.forms` gains the ADR form exactly as COMMON-DOC-FORM-1 1.0.0 defines it (`roles[2]`): `form_id` `adr`, `title` `ADR`, Context (Problem and Drivers, Decision Scope), Decision (Chosen Option, Authority and Effect), Alternatives (Considered Options, Trade-offs), Consequences (Impacts, Follow-up) and Traceability (Sources, and Supersession, which is conditional on a predecessor or successor decision existing), with `link_only` false everywhere. Templates keep their H1.
- **Local extension (W03-D03).** One registered conditional local H3 `Lifecycle Traceability` under Traceability (`adr-lifecycle-traceability`), whose verification is the body-contract check, with its condition, owner, review and removal recorded as for the other forms.
- **Retained form (W03-D02, W03-D52).** One `retained_form` extension, `adr-accepted-retained-form`, carries the seven H2 the profile requires today (Overview, Context, Decision, Explicit Non-goals, Consequences, Alternatives, Traceability) as its retained lists, moved unchanged from the profile, the status `accepted`, and a closed identity bound that matches ADR-0001 to ADR-0061 and nothing else. The retained lists apply to a document only when its status is in the extension's statuses and its path-derived identity matches the bound; every other document of the role is checked against the form tree. Its removal criterion is that no ADR in the range remains in the tree, each having been replaced by a successor; the bound is never widened.
- **Identity bound.** A retained form may carry `identity_bound`, an anchored regular expression over the artifact identity; this package's value matches exactly the sixty-one identities ADR-0001 to ADR-0061. The registry check refuses a bound that does not compile or is not anchored, a retained form of the ADR role without one, and a bound of the ADR role that matches ADR-0062, the first identity outside the range, so the range cannot be widened unnoticed. A retained form without a bound keeps selecting by status alone, as the kind was defined.
- **Profiles and binding.** `sdlc/architecture-decision` and its template twin keep `document_role` `adr` and carry empty H2 lists. The body contract stays as it is: section `Traceability`, table heading `Lifecycle Traceability`, the columns `Decision lineage`, `Replacement relation` and `Affected Spec`, and the enforced status `proposed`. No path pattern, frontmatter list or lifecycle domain changes.
- **Layer key (W03-D22, W03-D52).** `FM-LAYER-ADR` allows `layer` on any ADR whose status is `accepted`, while W03-D22 keeps the key only on the existing accepted ADRs and never adds it to a new document. The rule therefore also requires the identity to match the retained form's bound, ADR-0001 to ADR-0061, so both accepted-ADR exceptions share the one discriminator of W03-D52 and an ADR after ADR-0061 can never carry `layer`; the `layer` entry of `frontmatter_keys` and its tests say so.
- **Tables (W03-D08, W03-D57).** COMMON-ROLE-FORMS names the ADR table as alternative and trade-off, and no ADR holds such a table. The TemplateDefinition records `Alternatives` in `adr-alternatives-trade-offs` with the keys `Alternative` and `Trade-off` (both required), `minimum_rows` 0 and row identity `Alternative`, and `Lifecycle Traceability` in `adr-lifecycle-traceability` with its three body-contract columns, `minimum_rows` 1 and row identity `Decision lineage`. Nothing is renamed. The other two items COMMON-ROLE-FORMS names for the role need no table: Supersession is the form's conditional H3, and Owner and Approval is covered by Decision > Authority and Effect, where ADR-0062 states its decision maker.
- **TemplateDefinition and record (W03-H13).** `common/template-sdlc-architecture-decision` stores the eleven definition keys of SPEC-0196: purpose, responsibility, non-goals, policy references (`document-authoring.md`, `sdlc.md`), vocabulary reference (`.agents/knowledge/glossary.md`), applicability, every real consumer path for its profile, validation cases, migration, `tables`, and `contract_version` `COMMON-DOC-FORM-1/` followed by `common_forms.version`. The 19-field record that `template_definition_record` derives for it passes `REGISTRY_TEMPLATE_RECORD` against the schema copy; its `extensions` field lists both extensions of the form.
- **Template.** The decision template takes the form's five H2 and ten H3 with an author prompt under each H3, the `Alternatives` and `Lifecycle Traceability` tables and its frontmatter. Every former prompt is placed: the Overview prompt under Chosen Option, the two Context prompts under Problem and Drivers and Sources, the two Decision prompts under Chosen Option and Authority and Effect, the Explicit Non-goals prompt under Decision Scope, the Consequences prompt under Impacts, the Alternatives prompt under Trade-offs and the Traceability prompt above the `Lifecycle Traceability` table. An H3 that no former prompt fits gets a prompt that restates the form's content for it. The template's `version` stays `0.1.0`, the starting value of a new document.
- **Registry Schema Version (SPEC-0207, W03-D66).** The new optional `identity_bound` property is a new key of `form_extension`, whose schema sets `additionalProperties: false`, so a strict consumer rejects it and the step is MAJOR under REQ:878. The implementation commit applies the next MAJOR number over the value on `main` at landing to the registry `schema_version`, the schema `const`, `REGISTRY_MAJOR`, appends it to `READABLE_REGISTRY_MAJORS` in `scripts/document_authority.py` and edits `DOC_REGISTRY_MAJOR` in `scripts/provider_write_guard.py`; the version-pinning tests derive their literals from those constants (SPEC-0207), so no test edit follows. The Task records the level and the reason as evidence.
- **Amending ADR (W03-D52).** ADR-0062, the next free identity after SPEC-0207's ADR-0061, is written in the common form and is the first document to use it. It narrows Decision 5 of ADR-0059 by dated clarification and replaces no paragraph: the H2 lists and list checks of profiles leave as Decision 5 says, with the change that moves the last role; the retained H2 lists of the accepted ADRs in the closed range stay, with their checks, as a registered extension under Decision 2 until a successor replaces each of those ADRs; and an ADR outside the range takes the common form in every status. ADR-0059 keeps every other clause. ADR-0062 is created `proposed` with the implementation, names the current user as decision maker, and becomes `accepted` only by the user's recorded approval in its own commit; that acceptance accepts no criterion of this package by itself. In that same commit ADR-0059 gains one paragraph, a dated current-state clarification that states the narrowing and links ADR-0062, with a patch raise of its `version`, so it never cites a decision that is not in force. This follows the pattern of ADR-0055 and of SPEC-0185, where each ADR that ADR-0060 narrowed gained such a paragraph, and it is the only change to an accepted ADR.
- **Policy text.** The document authoring policy adds the ADR to the roles that use their registry forms and states the accepted-ADR exception by its identity range; the Stage 99 README says the same; `docs/02.architecture/AGENTS.md` says a new ADR starts from the common form and an accepted ADR in the range keeps its form until replaced.

## Core Design

[AD-0006](../../02.architecture/descriptions/0006-workspace-agent-governance-platform.md) owns the governance view; no component changes. The registry stays the single machine owner of document form ([ADR-0033](../../02.architecture/decisions/0033-common-document-contract-v9.md) as amended by [ADR-0059](../../02.architecture/decisions/0059-registry-common-form-model.md)); this package adds ADR-0062, which narrows ADR-0059 Decision 5, adds the dated clarification to ADR-0059 and changes no other ADR.

## Data Modeling & Storage Strategy

Registry data: one form with two extensions, one TemplateDefinition with two tables, two profiles' lists and one new extension field. Documents: one template, one new ADR and one dated paragraph in ADR-0059. Code: the retained-form selection, one registry check, one frontmatter rule, and tests.

## Interfaces & Data Structures

- `scripts/document_contracts.py`: `FormExtension` gains the optional `identity_bound`; `CommonForm.retained_headings` takes the status and the artifact identity and returns the retained lists only when both match; `REGISTRY_FORM_EXTENSION` covers the bound.
- `scripts/validate-markdown-profiles.py`: the body check passes the path-derived identity it already computes for `ARTIFACT-IDENTITY`.
- `tests/test_common_form_tree.py`, each new case failing first: an accepted ADR inside the range passes in the retained form and fails in the common form; an accepted ADR outside the range passes in the common form and fails in the retained form; a proposed ADR uses the tree whatever its identity; a retained form without a bound still selects by status; an unanchored or uncompilable bound fails the registry check, and so does a bound of the ADR role that matches ADR-0062. The existing case that expects the tree to fail for every accepted ADR is rewritten for the two identities and is not weakened. The ADR profiles gain their form, the exact form count grows by one, `FORM_TEMPLATES` gains the decision template, and the record tests of SPEC-0196 cover the new definition.
- `tests/test_frontmatter_key_contract.py`: `layer` on an accepted ADR outside the range fails and inside it passes; `layer` on an ADR that is not accepted still fails.

## Edge Cases & Error Handling

- The merge order is SPEC-0188, SPEC-0189, SPEC-0191 to SPEC-0197, then this package. SPEC-0196 supplies `contract_version`, the schema copy and `REGISTRY_TEMPLATE_RECORD`; SPEC-0193 supplies `relationship_contract`, from which the record's relationships are derived; SPEC-0192 supplies the generator, whose output for a new ADR follows the new template.
- The link validator's lifecycle evidence reader also derives heading validity from the form lists. For a retained ADR that flag is false, and it is read only for Tasks, so that reader is left unchanged; the Task confirms that the 36 ADRs gain no diagnostic from the four strict validators.
- The table checks report nothing for a retained ADR: the `Alternatives` table has no minimum row and its section is absent there, and the `Lifecycle Traceability` table belongs to the body contract, which is enforced only for `proposed`.
- ADR-0062 names this Spec as its affected Spec while the package is open; the package exit rewrites that one cell to the left-the-tree form, as earlier exits did for ADR-0059 and ADR-0060.
- The identity range also holds numbers whose ADR has left the tree; `LIFECYCLE-IDENTITY-REUSE` already refuses to mint them again.
- If another package takes ADR-0062 first, the author stops and asks the user: extending the retained range would need a new user decision, because W03-D69 fixed it at ADR-0061.

## Failure Modes & Fallback / Human Escalation

If any accepted ADR gains a diagnostic or would need an edit beyond the one paragraph in ADR-0059, if the retained lists cannot be moved unchanged, or if ADR-0061 of SPEC-0207 is not `accepted` when this package starts (the retained form applies to accepted ADRs only and ADR-0061 is written in the old form), or if the user does not accept ADR-0062, the author stops and asks the user; without that acceptance the package does not complete. If any document outside the named scope gains a diagnostic, the change is wrong and is fixed before commit.
